# 字段捷径额度切换（v1.0.5）

字段捷径的购买、剩余次数和有效期由飞书字段捷径平台管理。开发商后端只为通过验签的字段捷径请求提供物流查询，不查询、不初始化、不扣减共享额度表。边栏插件仍使用自身的额度规则和充值流程，不需要迁移数据库。

## 上线顺序

1. 在飞书字段捷径中心核对付费方案和目标使用期限。若要采用一周有效期，应由飞书侧设置并验证；不要在开发商后台给字段捷径另发次数。记录正式捷径分享链接最后的 `packID`，不要使用本地调试 ID。
2. 先将 `field-shortcut-v1.0.5-feishu-quota-2026-11-25.zip` 上传飞书，确认已有表格切换到能发送飞书签名的版本。旧包未附带签名，后端切换后会拒绝旧包的查询。若平台不允许直接升级原商品，先确定已有用户的升级安排，再切换后端。
3. 核对旧字段测试收银台没有待处理的真实订单；如有，先对账处理。备份宝塔项目现有 `field-server/index.mjs`，然后用后端补丁中 `field-server/` 下的两个文件更新对应路径。保留 `server/`、边栏前端、原 `.env`、Nginx 和数据库不变。不需要部署整个历史一体化包。`site/field/` 中的说明页仅更新字段捷径说明，可与该补丁一同更新。
4. 在现有 `.env` 增加 `FIELD_FEISHU_PACK_IDS=正式捷径ID`（多个用逗号分隔），保留原物流凭据和边栏付款配置。重启现有的一体化 Node 服务。不要把 `.env` 放进任何上传包。

## 验收

- 用飞书真实测试租户验证：飞书有可用次数、边栏额度为 0 时，字段捷径仍返回物流结果；查询后边栏额度无变化。飞书权益耗尽时，应由飞书提示，并且不请求物流接口。
- 在边栏验证充值入口照常可用；有额度时查询正常扣次、无额度时继续拦截。
- `/field/api/express/query` 空参数应返回 400，合法参数但没有可信签名应返回 401；字段专用的旧收银台和额度接口不再对外开放。字段捷径的飞书充值入口不是这些旧接口。

若需要回退，先评估旧后端恢复后是否会重新消费共享额度，再从备份恢复字段后端。不要改边栏或数据库记录来补偿切换。
